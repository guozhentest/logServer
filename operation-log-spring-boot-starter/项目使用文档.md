# 操作日志组件使用指南 (operation-log-spring-boot-starter)

## 一、组件介绍

本组件提供了一套 **全服务类型的操作日志自动记录与查询** 解决方案。医院项目只需引入该依赖，执行一次建表脚本，并在需要记录日志的方法上添加 `@OperationLog` 注解，即可自动记录请求入参、出参、耗时、操作人等信息，并可通过内置的 HTTP 接口进行查询。

**主要特性：**
- 零代码侵入，注解驱动自动记录日志
- 支持全服务类型（HIS、TH‑API、IM、第三方服务等）
- 内置查询接口，支持按机构、用户、业务类型、服务类型、响应状态等多维度检索
- 异步保存，不影响主业务性能
- 查询接口强制签名校验（MD5 + 时间戳），5分钟内有效
- 强制机构一致性校验，防止跨机构数据泄露
- 业务类型与服务类型通过字典表动态配置，支持管理后台实时更新
- **启动时自动向中心 Agent 注册机构信息与字典，实现即插即用的智能查询**（需配置）

## 二、接入步骤

### 1. 引入 Maven 依赖

在项目的 `pom.xml` 中添加：

```xml
<dependency>
    <groupId>com.leantech</groupId>
    <artifactId>operation-log-spring-boot-starter</artifactId>
    <version>2.0.0</version>
</dependency>
```

### 2. 依赖前置要求

本组件依赖 **MyBatis-Plus** 进行数据库操作。若您的项目尚未引入 MyBatis-Plus，请添加以下依赖（**强烈建议使用 3.4.3.4 或更高版本**）：

```xml
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-boot-starter</artifactId>
    <version>3.4.3.4</version>
</dependency>
```

### 4. 配置文件

在 `application.yml` 中添加配置。以下为全量配置项及其默认值：

```yaml
operation:
  log:
    enabled: true                         # 是否启用组件
    compress-body: false                  # 是否压缩大字段（请求/响应体）
    use-dict-table: true                  # 是否启用字典表（默认启用，强烈推荐）
    user-info:
      attribute-key: XCX_LOGIN_INFO       # 用户信息在 request 中的 attribute key
      user-id-field: userId               # 用户对象中 userId 字段名
      fixed-org-code: ${th.organizationcode:} # 机构代码，支持占位符引用已有配置
    header:
      trace-header-name: x-trace          # 登录会话ID 的请求头名称
    dynamic-param:
      api-name-param: method              # 接口名称参数名
      describe-param: methodDescribe      # 操作描述参数名
      sub-biz-param: subBizType           # 子业务类型参数名
    api:
      enabled: true                       # 是否启用内置查询接口
      api-key:                            # 【必填】API 签名密钥，务必配置
      max-limit: 1000                     # 单次查询最大返回条数
      body-truncate-length: 500           # 响应体预览截断长度
    agent:
      register:
        enabled: true                     # 是否启用自动注册到中心Agent
        agent-url:                        # 中心Agent服务地址，例如 http://agent-center:8081
        org-name:                         # 机构名称，默认使用 th.organizationname
        org-code:                         # 机构代码，默认使用 th.organizationcode
        base-url:                         # 本机构服务地址，默认自动拼接 http://server.address:server.port
        api-key:                          # API签名密钥，默认共享 operation.log.api.api-key
```

> **必填项说明：**
> - `api-key`：查询接口的签名密钥，未配置则查询接口不可用。
> - `fixed-org-code`：建议通过 `${th.organizationcode}` 引用现有配置。
> - 若希望使用中心智能查询，请配置 `agent.register.agent-url`。

### 5. 初始化 TraceId（推荐）

在过滤器或拦截器中调用 `TraceIdUtil.init()` 以生成业务语义化 TraceID，串联整个请求链路。若项目已有类似机制，可在现有 Filter 中增加调用。示例：

```java
import com.leantech.oplog.util.TraceIdUtil;
import org.springframework.web.filter.OncePerRequestFilter;
import javax.servlet.FilterChain;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

public class TraceFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain) {
        String orgCode = request.getHeader("X-Org-Code");
        String userId = request.getHeader("X-User-Id");
        String loginId = request.getHeader("X-Login-Id");
        try {
            TraceIdUtil.init(orgCode, userId, loginId);
            chain.doFilter(request, response);
        } finally {
            TraceIdUtil.clear();
        }
    }
}
```

> 若未手动初始化，组件会尝试从 `request.setAttribute("XCX_LOGIN_INFO")` 和请求头 `x-trace` 中自动提取信息。

## 三、使用注解记录日志

### 1. 基础用法

在 Service 方法上添加 `@OperationLog` 注解：

```java
import com.leantech.oplog.annotation.OperationLog;
import com.leantech.oplog.enums.BizType;

@Service
public class HisAppointmentService {

    @OperationLog(value = "查询HIS号源", bizType = BizType.REG)
    public HisNumberListResponse queryNumberList(HisNumberListRequest request) {
        // 业务逻辑
        return hisClient.queryNumberList(request);
    }
}
```

### 2. 动态描述（推荐）

若方法参数中包含 `method` 和 `methodDescribe`，可省略 `value`，组件会自动提取：

```java
@OperationLog
public JSONObject sendHisApi(String method, String methodDescribe, JSONObject reqParam, boolean isThrow) {
    // 方法逻辑
}
```

### 3. 注解参数说明

| 属性 | 类型 | 说明 |
| :--- | :--- | :--- |
| `value` | `String` | 操作描述，优先级最高。若为空则从 `methodDescribe` 参数获取 |
| `bizType` | `BizType` 枚举 | 业务类型：`REG`(挂号)、`PAY`(缴费)、`CLI`(实名认证/门诊)、`ONLINE`(在线问诊)、`INP`(住院)、`DRUG`(药房)、`EXA`(检查检验)、`SYS`(系统)、`OTHER`(其他) |
| `bizTypeCode` | `String` | 业务类型编码（字符串形式，优先级低于 `bizType`） |
| `subBizType` | `String` | 子业务编码，如 `001`、`MI` 等 |
| `serviceType` | `ServiceType` 枚举 | 服务类型，如 `HIS`、`TH_API`、`IM` 等；不填则按类名自动推断（通过字典表） |

### 4. 自动推断机制

- **业务类型**：若未显式指定，将依次通过参数名（`bizType`/`type`）、参数值（`String` 类型且匹配枚举）、字典表关键词匹配进行推断，最终默认 `OTHER`。当多个关键词同时命中时，选择 `sort_order` 最小的类型（优先级最高）。默认配置已确保“在线问诊”优先级高于“挂号”。
- **服务类型**：根据当前类的全路径前缀与字典表 `class_keywords` 匹配；若未匹配则默认 `SYS`。

### 5. 内部调用处理（重要）

Spring AOP 通过动态代理拦截方法，**类内部直接调用（`this.method()`）会导致切面失效**。您可选择以下任一方案解决：

#### 方案一：自注入（推荐，无需 JVM 参数）
1. 在类上添加 `@SelfInject` 注解。
2. 声明一个与注解同名的字段（默认 `self`），Spring 会自动注入代理对象。
3. 将内部的 `this.xxx()` 调用改为 `self.xxx()`。

```java
@SelfInject
@Service
public class HisOnlineService {
    private HisOnlineService self;  // 自动注入代理

    @OperationLog
    public JSONObject sendHisApi(...) { ... }

    public JSONObject doSomething() {
        return self.sendHisApi(...);
    }
}
```

#### 方案二：AspectJ 加载时织入（零代码修改，需 JVM 参数）
如需完全零侵入，可在启动命令中添加 `-javaagent` 参数（与加密 Starter 使用方式相同），由 AspectJ 自动拦截内部调用。具体配置请联系架构组获取支持。

## 四、查询日志接口

组件启动后自动暴露 `POST /operation-log/query` 接口。

### 1. 签名校验（必读）

所有请求必须携带以下 Header：

| Header | 说明 |
| :--- | :--- |
| `X-API-Sign` | 签名值，`MD5(apiKey + orgCode + timestamp)` |
| `X-API-Timestamp` | 当前毫秒时间戳，有效期 5 分钟 |

**签名生成示例（Java）：**
```java
String raw = apiKey + orgCode + timestamp;
String sign = DigestUtils.md5DigestAsHex(raw.getBytes(StandardCharsets.UTF_8));
```

### 2. 机构一致性校验

请求中的 `orgCode` 必须与医院配置的机构代码完全一致，否则返回 403。

### 3. 请求示例

```http
POST /operation-log/query
Content-Type: application/json
X-API-Sign: 5d41402abc4b2a76b9719d911017c592
X-API-Timestamp: 1713859200000

{
  "orgCode": "12341203485880770X",
  "userId": "3",
  "bizTypeCode": "REG",
  "responseStatus": "FAILURE",
  "startTime": "2026-04-22T00:00:00",
  "endTime": "2026-04-23T00:00:00",
  "page": 1,
  "size": 20
}
```

### 4. 请求参数说明

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `orgCode` | String | 是（用于签名及机构校验） | 机构代码 |
| `userId` | String | 否 | 用户工号 |
| `loginId` | String | 否 | 登录会话ID |
| `traceIdPrefix` | String | 否 | TraceID 前缀（模糊匹配） |
| `bizTypeCode` | String | 否 | 业务类型编码 |
| `serviceType` | String | 否 | 服务类型 |
| `responseStatus` | String | 否 | `SUCCESS` 或 `FAILURE` |
| `startTime` | DateTime | 否 | 开始时间（ISO 8601格式） |
| `endTime` | DateTime | 否 | 结束时间 |
| `page` | Integer | 否 | 页码（默认 1） |
| `size` | Integer | 否 | 每页条数（默认 20，最大受配置限制） |

**URL**：`POST /operation-log/dict/refresh`  
**Header**：需携带签名 `X-API-Sign` 和 `X-API-Timestamp`。

## 六、自动注册到中心 Agent

### 1. 功能说明

启用该功能后，项目启动时会自动将本机构的 **基本信息、业务类型字典、服务类型字典** 上报到指定的智能查询中心（Agent），从而实现自然语言查询操作日志。  
注册采用异步方式，失败不影响业务运行。

### 2. 配置项

```yaml
operation:
  log:
    agent:
      register:
        enabled: true                  # 开启自动注册
        agent-url: http://agent-center.example.com:8081  # 中心Agent地址（必填）
        org-name:                      # 机构名称，默认使用 th.organizationname
        org-code:                      # 机构代码，默认使用 th.organizationcode
        base-url:                      # 本机构接口地址，默认自动拼接 http://服务地址:端口
        api-key:                       # API签名密钥，默认共享 operation.log.api.api-key
```

> **提示：**
> - 若不希望自动注册，将 `enabled` 设为 `false` 即可。
> - 机构名称 `org-name` 通常无需配置，会自动读取医院原有的 `th.organizationname`。
> - 接口地址 `base-url` 通常也无需配置，组件会自动获取当前服务器的 IP 和端口。

### 3. 注册内容

自动上报的数据包括：
- `orgCode`、`orgName`、`baseUrl`、`apiKey`
- 该机构在 `operation_biz_type_dict` 表中所有启用的业务类型
- 该机构在 `operation_service_type_dict` 表中所有启用的服务类型

### 4. 验证

启动项目后，查看日志中是否出现：

```
正在向中心注册：http://agent-center:8081/admin/hospital/register，机构代码：12341203485880770X
注册结果：{"code":0,"message":"注册成功，已同步业务/服务类型配置"}
```

出现上述日志即表示注册成功。此后便可通过大模型智能查询该机构的操作日志。

## 七、常见问题

### Q1：日志未保存到数据库？
- 检查 `operation.log.enabled` 是否为 `true`。
- 确认方法是否通过 Spring 代理调用（不能是内部 `this.xxx()`，除非已采用自注入或 LTW）。
- 检查字典表是否已初始化。

### Q2：`orgCode` 或 `userId` 显示为 `UNKNOWN`？
- 确认请求头 `x-trace` 是否携带。
- 检查 `request.setAttribute("XCX_LOGIN_INFO", userInfo)` 是否正确执行，且对象有 `getUserId()` 方法。

### Q3：查询接口返回 401 或 403？
- 确认已配置 `operation.log.api.api-key`。
- 签名计算方式：`MD5(apiKey + orgCode + timestamp)`，时间戳为毫秒级。
- 确认 `orgCode` 与医院自身配置的机构代码一致。

### Q4：业务类型没有被自动识别？
- 检查字典表 `operation_biz_type_dict` 是否包含对应的关键词。
- 若自定义了关键词，请确保配置 `operation.log.biz-type-keywords` 中已包含（注：字典表模式默认不读取该配置）。
- 如需调整优先级，修改 `sort_order` 值即可（越小优先级越高）。

### Q5：内部调用导致日志缺失？
- 使用 `@SelfInject` 注解，并将 `this.method()` 改为 `self.method()`。
- 或启用 AspectJ LTW，由架构组提供 `-javaagent` 配置。

### Q6：自动注册失败怎么办？
- 检查 `agent-url` 是否可达。
- 确认中心服务是否已启动。
- 注册失败不会影响业务日志的本地记录，可稍后重试或手动调用注册接口。
